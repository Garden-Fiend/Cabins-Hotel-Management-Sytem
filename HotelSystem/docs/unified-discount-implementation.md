# Unified discount implementation report

## Pre-implementation audit and feasibility

The app is a React/TypeScript frontend whose ReservationDemoProvider already
holds reservations, stays, guests and HotelConfigurationData in memory. Its
existing discount definitions were editable defaults for the manual form, with
no stable target, currency, source identity or final-price method. Price lines
stored base amounts and summaries stored calculated reductions, but neither
explicitly represented effective unit prices or original unit-rate quantities.
Manual room scope intentionally included extras. All discounts ran in saved
list order. Detail and print pages read saved summaries rather than live rates.

An incremental extension was feasible: preserve the existing configuration array,
base-rate resolver and authoritative reservation calculator. Add applicability
and money helpers; extend snapshots; replace only the Discounts editor and the
preset-as-manual-prefill interaction. No second calculator or backend is needed.
The implementation followed this assessment before file changes began.

## Reused, extended and replaced responsibilities

Reused without modification: ReservationDemoProvider, useReservationDemo,
useHotelConfiguration, routing, hotel-time helpers, lifecycle logic, the tax
placeholder, and historical demoReservations/datasample fixture values.

Extended: reservation/configuration types, sample discount definitions, the
room-price resolver, reservationPricing, ReservationPane, detail and print pages.

Replaced: the generic configuration discount form with DiscountPresetsEditor,
and the reservation definition-prefill selector with contextual read-only
presets plus a separate manual editor. Legacy manual scope and ordering are
retained explicitly for legacy snapshots.

## Data structures

- DiscountDefinitionConfiguration: id, label, scope, method, value, enabled,
  currency, targetRoomTypeId/targetItemId, discountedUnitPrice or rate entries.
- Room rate entry: stable existing rateId and discountedUnitPrice. Nightly
  discounts reference one nightly base rate, not separate multi-night durations.
- ReservationDiscount: existing manual fields plus sourcePresetId/name, captured
  target IDs, rate ID, currency, original/applied unit prices, quantity and time.
- AppliedDiscount: calculated amount, application order and line allocations,
  with captured selection metadata. No live definition is needed to display it.
- ReservationPriceLine: original amount, baseUnitPrice, pricingQuantity, target
  metadata, effectiveAmount/unit price after replacement, finalAmount after all
  discounts. Original amounts are never overwritten by preset reductions.
- ReservationRoomSnapshot: captured base total plus unit price, rate ID and quantity.
- ReservationPriceSummary: original subtotal, all actual discount reductions,
  adjustments, amount owed and optional pipelineVersion: 2.

Optional fields preserve compatibility with the existing historical fixtures.
Validators reject invalid scope/method/target combinations before new selection.

## Applicability and calculation

New selection matches enabled presets to active room types/rates or chargeable
catalog product IDs, validates currency and final price bounds, and respects
partial coverage. Retiring a different covered rate does not hide an otherwise
applicable active rate. Reservation presets are global, require explicit Apply,
and do not perform personal eligibility checks.

Version 2 calculates final-price overrides, then room/item fixed or percentage
reductions, then reservation-wide reductions; insertion order is stable within
each stage. One room/item selector applies one preset at a time. The calculator
also rejects competing final-price overrides. Manual room scope still includes
the room's extras, whereas configured room presets target accommodation only.
Item fixed amounts reduce the selected line total; final item prices are per unit.

Every reduction is capped at the remaining eligible amount. Unit prices round
before quantity multiplication; allocations use integer minor units. Signed
adjustments are added separately. The invariant is:

`amountOwed = max(0, originalSubtotal - totalDiscounts + adjustmentTotal)`

## Historical stability

Configuration is used to choose new presets, never to recalculate saved applied
values. Opening records keeps captured unit prices, quantities, names, rates,
dates and actual timestamps. Unrelated edits preserve those values. Compatible
quantity/night changes deliberately recalculate; incompatible target/rate changes
warn and block saving until explicitly corrected. Removal gives feedback.

Legacy manual records preserve list ordering until a preset is explicitly added.
New records store version 2. Legacy nightly quantity, when absent, is inferred
from saved hotel-local stay dates; newly saved records capture quantity directly.
The fixture data itself is unchanged. Print and detail breakdowns read snapshots.

## Verification and limits

Final verification from HotelSystem:

- `npm test`: passed, 101 tests across 16 files (54 added tests, 47 existing tests).
- `npm run lint`: passed.
- `npm run build`: TypeScript and Vite build passed. The generated JavaScript
  chunk is approximately 517 kB and triggers Vite's 500 kB bundle-size warning.

Tests include the original regression suite and new applicability, pricing,
builder, state/history and print coverage; no existing test was deleted.

The system remains in memory and resets on reload. There is no backend, coupon
system, promotion scheduling, automatic eligibility, payment ledger, VAT/tax
compliance or per-physical-room rate override. No dependencies were added.
Browser rendering and physical/thermal printer output were not manually tested.
The production build may report the existing large-bundle warning; code splitting
is outside the discount implementation.

## Dedicated discount module

Discount management now lives at `/discounts`, reached through the shared sidebar.
The editor, builder tests and preset types live under `src/features/discounts/`.
Configuration continues to hold the shared in-memory data, room prices and item
catalogs; discount calculation remains in the existing shared pricing pipeline.
The configuration page no longer contains discount controls. Route regression
tests exercise direct entry and preservation of presets when navigating pages.
This extraction also updates `src/app/router.tsx` and
`src/app/layouts/AppLayout.tsx`, and adds `src/pages/DiscountsPage.test.tsx`.
